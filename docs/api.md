# API reference

Interactive schemas are generated by FastAPI at `/docs`; the machine-readable schema is `/openapi.json`.

## Authentication

Team calls use `Authorization: Bearer <team-key>`. Admin endpoints use a separate admin credential. Metrics accept either the read-only metrics credential or the admin credential. Provider credentials are server-side environment values and are never accepted from the chat request.

## Endpoints

| Method | Path | Credential | Purpose |
| --- | --- | --- | --- |
| GET | `/health/live` | None | Process liveness |
| GET | `/health/ready` | None | Control-state and audit-store availability |
| POST | `/v1/chat/completions` | Team | Chat completion or SSE stream |
| GET | `/metrics` | Metrics or admin | Prometheus exposition |
| GET | `/admin/teams/{team}` | Admin | Policy and current UTC-day spending |
| PUT | `/admin/teams/{team}/policy` | Admin | Replace a validated team policy |
| GET | `/admin/providers` | Admin | Per-worker circuit state |
| GET | `/admin/audit` | Admin | Latest 100 metadata events |

## Chat request

```json
{
  "model": "balanced",
  "messages": [{"role": "user", "content": "Explain a circuit breaker."}],
  "max_tokens": 64,
  "temperature": 0.0,
  "stream": false,
  "priority": "interactive"
}
```

The model is an allowed route alias. Messages support text-only `system`, `user`, and `assistant` roles. System messages must come first. At least one user message is required. Each content string is limited to 32,000 characters; the combined content limit is 64,000 UTF-8 bytes. A team's injected system message is included in revalidation.

`max_tokens` is 1 to 4096. Priority is `interactive` or `batch`. Temperature is 0 to 2 in the shared request schema; Anthropic rejects values above 1 as an unsupported request parameter. Unknown fields, tool calls, attachments, and vendor-specific request options are rejected.

## Normal response

```json
{
  "id": "server-generated-request-id",
  "object": "chat.completion",
  "model": "balanced",
  "choices": [{"index": 0, "message": {"role": "assistant", "content": "Example answer"}, "finish_reason": "stop"}],
  "usage": {"prompt_tokens": 29, "completion_tokens": 12, "total_tokens": 41},
  "gateway": {
    "provider": "primary",
    "served_model": "mock-primary",
    "accounted_microusd": 265,
    "cost_estimated": false
  }
}
```

The example uses fictional mock pricing. `usage` describes the final completion, not accumulated retries. It may be null when the provider omits usable token metadata. Request cost includes all attempts, including conservative failed-attempt debits. `cost_estimated` identifies an estimate anywhere in that request. Finish reasons normalize to `stop` or `length`.

## Streaming

Set `stream: true` to receive `text/event-stream`. Each `data:` record contains a normalized completion chunk. The final chunk contains usage and accounting metadata, followed by `data: [DONE]`. Intermediate chunks identify the actual provider and served model.

An interrupted stream emits a record such as:

```json
{"error": {"code": "stream_interrupted", "message": "Provider stream ended unexpectedly"}}
```

Receiving `[DONE]` does not make an earlier error disappear. Applications must inspect all records and decide whether to display partial content or retry as a new request. The gateway provides no idempotency guarantee for a caller's retry.

## Errors

| Status | Typical code | Meaning |
| --- | --- | --- |
| 401 | `unauthorized` | Team credential missing or invalid |
| 403 | `model_forbidden` | Team cannot use that alias |
| 402 | `budget_exceeded` | Next attempt cannot be reserved within the daily allowance |
| 422 | Validation error or `token_bound_exceeds_quota` | Bad input or a request too large for the team's token capacity |
| 429 | `rate_limited` | Team token/request bucket is exhausted; inspect `Retry-After` |
| 502 | Provider rejection | Nonretryable upstream error; no failover |
| 503 | `providers_unavailable`, `gateway_busy`, or infrastructure failure | No eligible capacity/provider or unavailable control plane |
| 504 | `deadline_exceeded` | The total gateway deadline elapsed |

Gateway error payloads include a stable code, safe message, and request ID. Upstream response bodies are not reflected to the caller. Request validation errors use FastAPI's standard `detail` format.
